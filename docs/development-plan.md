# Pare 开发计划

> 阶段 0、阶段 1 的只读扫描纵切片、阶段 2 的首个规则/计划切片和阶段 3 的同卷隔离/撤回已经实现并通过本机验证。其余阶段仍是路线，不代表相关功能已经可用。

## 阶段 0：接口和测试夹具（已完成）

- 建立 Go 模块、CLI 参数解析和版本化 JSON schema。
- 设计扫描记录：路径节点与文件身份分开；数字 ID 在 JSON 中保留精度。
- 准备临时目录样本，覆盖长路径、硬链接、reparse point、不可访问项和扫描期间变更。
- 已完成：Go CLI 入口、`pare.scan/1` 报告模型、十进制字符串整数、扫描接口、可注入遍历测试后端。
- 已验证：schema 版本和错误类型测试；扫描测试只使用临时目录；Windows API 实现使用固定版本的 `golang.org/x/sys`，依赖许可见 `THIRD_PARTY_NOTICES.md`。

## 阶段 1：只读目录扫描（首个纵切片已完成）

- 已完成：Win32 批量目录枚举、取消、错误分类、不穿透 reparse point、路径节点和 `pare.scan/1` JSON 命令；测试覆盖 Unicode、长路径、reparse、重复文件 ID 与不完整报告。
- 尚未完成：全卷对拍、目录汇总、硬链接去重口径、冷缓存测量和峰值内存报告。
- benchmark 当前只测本机热缓存下的合成目录树，并记录 Go 版本、OS、卷类型/文件系统、范围和条目数；性能目标留待可重复对比后确定。
- 验收：实际扫描只读且覆盖缺口明确；完整的多工具对拍和全卷验收在发布更广范围前补齐。

## 阶段 2：规则和计划（首个切片已完成）

- 已完成：`pare plan` 读取 `pare.scan/1`，用 4 条内置 E1 规则（用户 Temp、npm/pip/Go 构建缓存）生成 `pare.plan/1`；证据包括路径规则、属性、文件身份（硬链接阻断）、年龄、未变化与未占用探针；计划带 SHA-256 摘要和过期时间，`plan.Verify` 拒绝篡改和过期计划。
- 已验证：单元测试覆盖 unknown/error/冲突阻断、输入顺序无关的摘要、篡改/过期拒绝；Windows 探针测试覆盖未占用、被占用、已变化和已删除；本机 `AppData\Local` 扫描生成 1235 个候选，281 个可执行。
- 尚未完成：规则外部化与版本管理、注册表/已装软件探针、摘要签名（当前只防篡改不防伪造）、扫描器按文件记录卷序列号。

- 实现规则 schema、确定性匹配和探针结果类型。
- 只用少量测试规则验证用途证据与生命周期证据的组合；默认候选不自动勾选。
- 将规则命中展开为包含文件身份、证据、过期时间和摘要的逐文件计划。
- 验收：unknown/error/冲突证据不能生成可执行项；输入顺序改变时规范化计划摘要稳定；重放过期或被篡改计划会被拒绝。

## 阶段 3：隔离和撤回（同卷首版已完成）

- 已完成：`pare apply` 需用计划摘要确认，逐项先写 intent 再移动；移动前检查 reparse 父链，以无共享句柄锁定文件并复核身份，再用同一句柄不覆盖地改名到 `\.pare-quarantine\<批次>`；manifest 为 `pare.execution/1`。`pare undo` 按 manifest 撤回，原路径被占用时记为 conflict 并保留隔离文件，可重复执行。
- 已验证：真实文件测试覆盖错误摘要不移动、审批后被修改、被占用、篡改/过期计划、撤回冲突不覆盖、二次撤回、中断后的 intent 对账；CLI 冒烟走通 scan → plan → apply → undo。
- 尚未完成：保留期到期提示与单独确认的清空命令、manifest 写失败和权限不足的专门测试、跨卷隔离。

- 先做同卷普通文件隔离，逐项持久化状态和 manifest。
- 实现执行前身份复核、硬保护路径、reparse 父链检查、取消与崩溃后对账。
- 实现冲突安全的撤回；跨卷复制和系统维护另开阶段，不混入首版。
- 验收：审批后替换、锁定、权限不足、manifest 写失败、中途崩溃、重复执行和撤回冲突用例均不得覆盖或删除源文件。

## 阶段 4：便携桌面端

- 在 CLI schema 稳定后制作扫描进度、占用树、证据列表、计划审阅和执行状态界面。
- UI 只调用 Pare 核心，不复制规则或权限决策。
- 验收：无需登录或网络即可浏览本地结果；执行按钮只引用已审阅的计划摘要；界面清楚区分隔离量和实际空闲空间变化。

## 阶段 5：MFT 评估

- 依据阶段 1 的真实结果设定性能门槛，再评估成熟 NTFS parser。
- 固定依赖提交并完成许可证、边界行为和差分测试审查。
- 验收：只读解析器在损坏/变化卷上不崩溃、不误授权；失败能回退目录枚举并报告覆盖差异。未达到价值门槛则不实现。

## 阶段 6：发布准备

- 选定 UI 技术、项目许可证和 Windows 发布模式。
- 建立可重复构建、依赖来源清单、第三方通知和安全发布说明。
- 验收：干净 Windows 用户环境可以安装或直接运行；构建产物哈希、版本和来源可追溯；本地扫描无网络依赖。
