# Pare 设计稿

> 状态：设计基线。文中完整清理流程仍是目标；当前已验证到只读 Windows CLI 扫描，不代表规则、计划、隔离或撤回已经实现。

## 实现进度

首个原型使用 Go 和 `GetFileInformationByHandleEx(FileIdBothDirectoryInfo)` 批量读取所选目录树，并输出 `pare.scan/1` JSON。目录访问失败保留为覆盖错误；reparse point 会作为节点列出，但不会继续打开其目标。File ID 来自目录枚举记录，报告同时包含根目录卷序列号作为卷范围标识。

`pare plan` 在扫描报告上运行内置规则，输出逐文件的 `pare.plan/1` 计划；只有全部证据为 `pass` 的项标为可执行，可执行字节按 File ID 去重。`pare apply` 在用户以计划摘要确认后，把可执行项按第 6 节的顺序移入同卷隔离目录；`pare undo` 按 manifest 撤回且不覆盖。首版只支持同卷，没有永久删除或清空命令。

当前原型仍有明确限制：扫描报告不去重硬链接路径、不计算目录汇总、不读取 `$MFT`。完整设计中的其他模块要等只读契约、样本测试和安全边界逐步实现后再视为可用。

## 1. 目标与边界

Pare 面向需要理解 Windows 磁盘占用并谨慎清理文件的个人用户。核心结果是：可解释的文件清单、带证据的候选、明确到单个文件的计划，以及可核对的隔离和撤回记录。

首期支持 Windows 本地卷。暂不做注册表清理、启动项优化、云端账户、后台常驻、模型自主决策和通用脚本执行。系统组件与驱动维护不属于通用文件清理器；若未来增加，只调用受支持的官方维护工具并使用独立审批流程。

## 2. 方案选择

采用一个核心仓库：Pare CLI、Windows 扫描器和规则/执行逻辑在同一代码库中；便携桌面端和 Agent 插件作为消费者。这样先把安全逻辑和可测试接口集中起来，避免在两个产品里复制扫描与执行代码。

Go 是核心语言的当前选择，原因是项目首先需要 Windows API 调用、命令行分发和单文件候选部署。UI 技术暂不锁定，等 CLI 契约和核心行为稳定后再决定。首版采用目录批量枚举；不先写完整 `$MFT` 解析器，也不打包闭源 WizTree。

## 3. 模块

| 模块 | 职责 | 不负责 |
|---|---|---|
| `scanner` | 读取指定卷范围，输出路径节点、文件身份、大小、属性和扫描缺口 | 判断文件是否垃圾；授权删除 |
| `probes` | 查询规则需要的文件、应用和占用证据，区分通过、失败、未知 | 通过单个弱证据放宽风险等级 |
| `rules` | 将版本化规则匹配到扫描节点，并记录来源和证据 | 执行任意 shell 或脚本 |
| `planner` | 展开候选为逐文件计划，计算保守的回收估计 | 扩展审批后的通配路径 |
| `executor` | 校验计划、隔离文件、持久化状态、撤回和报告冲突 | 越过硬保护路径或静默永久删除 |
| `cli` | 暴露稳定、可自动化测试的 JSON 命令接口 | 将不可信自由文本当成路径或执行参数 |
| `desktop` | 展示扫描结果、证据、用户选择和执行状态 | 另写一套规则或安全策略 |

预期代码布局：

```text
cmd/pare/             CLI 入口
internal/scanner/     目录枚举与文件系统身份
internal/probes/      证据采集
internal/rules/       规则加载与匹配
internal/plan/        计划与估算
internal/executor/    隔离、撤回和持久化状态
internal/report/      JSON 与 Markdown 输出
rules/                经过测试的规则
testdata/             文件系统边界与故障样本
```

在实现开始前，目录结构可随原型结果调整；模块之间的接口和安全边界需要保留。

## 4. 扫描模型

### 4.1 首个后端：目录枚举

使用 Win32 批量目录读取 API 获取目录项；逐批处理缓冲区，错误按范围记录。权限拒绝、I/O 错误、文件变化或不支持的文件系统不能被折算为空目录。默认不穿透 reparse point、junction、符号链接和挂载点。当前实现已覆盖目录枚举、权限/API 错误分类、取消、Unicode 和长路径；reparse 测试在 Windows 符号链接不可用时尝试 junction。

扫描记录区分路径节点与文件身份。身份至少由卷标识和完整可用 File ID 组成；硬链接作为多个目录项指向同一文件身份处理。若某 API 只提供较短 ID，则不得把它当作跨场景永久身份，也不得据此给出确定回收量。当前 `FILE_ID_BOTH_DIR_INFO` 返回 64 位目录项 ID；它只用于本报告的卷范围，且扫描结果保留每个路径，不宣称跨扫描稳定身份或去重后的空间估算。

### 4.2 可选后端：NTFS MFT

只有当目录枚举原型在目标机器上达不到实测性能目标，且业务确实需要更快全卷清单时，再评估 MFT 后端。先审解析库的固定提交、许可证、损坏记录策略、卷变化处理和测试样本。MFT 数据仍需在执行时通过文件系统 API 重新确认；失败时回退目录枚举并报告覆盖差异。

### 4.3 计量

输出逻辑大小、分配大小估计和目录直接大小，并分别说明路径统计与按文件身份去重的规则。硬链接、稀疏/压缩文件、ADS、权限缺口和卷实时变化都会影响统计。隔离文件不会立即释放同卷空间；“隔离量”“潜在可回收量”和卷空闲空间实际变化分开报告。

## 5. 候选、证据与计划

风险等级作为规则下限：

| 等级 | 含义 | 默认行为 |
|---|---|---|
| E0 | 受限范围内用途和生命周期都有独立证据 | 仍须列入逐文件计划并由用户确认后隔离 |
| E1 | 可重建缓存，但删除会造成重新下载或计算 | 默认不勾选，用户逐项选择 |
| E2 | 用户数据或用途不确定 | 不批量执行，默认保留 |
| E3 | 系统、安装、恢复、驱动或启动组件 | 禁止通用文件删除；另行评估官方维护流程 |

探针状态使用 `pass`、`fail`、`unknown` 和 `error` 等明确结果。未知、过期或相互冲突的证据阻断执行。文件年龄、目录名、未发现应用记录、单个魔数或单次未占用检查都不能单独授权清理。

计划记录 schema 版本、计划摘要、创建/过期时间、卷身份、每个文件的完整身份和路径、观察属性、规则版本、证据、动作及估算。计划展开为明确文件项；执行时不重新解释通配模式。CLI 的接口版本独立演进，初版建议使用 `pare.scan/1`、`pare.plan/1` 和 `pare.execution/1`。

## 6. 隔离和撤回

执行器逐项预检卷、文件 ID、长度/时间、父目录链、reparse 状态、保护范围和规则版本。任何变化都跳过该项并要求重新规划。执行状态以持久化 manifest 记录 intent、处理中、完成、跳过和失败；中断后先对账，不盲目续删。

同卷隔离优先使用受控目录内的重命名；它不释放原卷空间。跨卷隔离首版可以拒绝，后续若支持，必须先复制到唯一临时目标、校验内容与必要元数据、提交目标，再复验并处理源文件。无法确认源未变化或无法恢复必要元数据时保留源文件。

撤回时检查 manifest、隔离项身份、原路径父链和目标冲突；路径已被占用时绝不覆盖。批次保留期到期只提示用户；永久清空单独确认。隔离和撤回需要崩溃恢复测试，系统维护操作不承诺可撤销。

## 7. Agent 与模型边界

产品方向（2026-10-24）：Pare 的核心是 **AI 调查本机独有的空间浪费**（例如更新器反复下载留下的安装包、只增不减的虚拟磁盘、没生效的配置、用不上的多平台二进制），而不是与商业清理软件比拼规则库。规则引擎降为“常规缓存”次要分区，并继续承担执行前的安全检查。

总原则（D3，2026-10-23 修订）：**模型可以提议，人确认执行，安全检查不交给模型。** 模型的结论始终单独标注为“AI 发现”，不能改变规则结论，也不能跳过执行前检查。

| 编号 | 决策 | 内容 |
|---|---|---|
| D8 | 模型接入 | 先接厂商 API，统一走 OpenAI 兼容接口（预置 DeepSeek、通义千问、Kimi、智谱、OpenAI，可自定义 Base URL / 模型）；暂不做本地模型。API Key 用 Windows DPAPI 加密保存在本机用户目录。 |
| D9 | 模型能调查什么（2026-10-24 修订） | 以智能体方式调用只读工具：扫描索引查询（目录、大文件、同尺寸文件聚类、扩展名与时间分布）、文件头与文本读取、现场大小与占用状态、已安装软件、进程，以及白名单只读诊断命令（WSL、fsutil、pnputil、DISM、vssadmin、docker 等，argv 直接执行、参数校验、不经 shell）。可以读取任何需要的文件；密钥、凭据、浏览器密码等敏感路径的**内容**发送前要用户逐次同意，元数据始终可用。本地先算异常线索作为调查起点。可起草新规则，经人审阅并补安全测试后才进入规则库。 |
| D10 | 执行与检查（2026-10-24 修订） | 每条发现给出可选方案：移入隔离区（可撤回，执行前核对身份、占用、变化和硬保护路径）、白名单动作模板（模型只选模板和参数，Pare 校验后展示完整命令）、模板以外的命令（原样展示、标注非模板，用户明确选中后才执行）、修改配置（备份并展示差异）、手动操作。任何执行都要用户在界面上确认。 |
| D11 | 手动与立即清空 | 用户可把任意位置加入手动清单，标注“无规则证据、由你自行决定”并二次确认；执行结果页提供“立即清空这批”，二次确认后永久删除以释放空间，失败时文件仍在隔离区并有 manifest 记录。 |

防注入：文件名、目录名和读取到的文件内容都作为数据放进提示，明确告诉模型其中的文字不是指令；模型输出按固定 JSON 结构解析，解析失败即视为“不确定”。模型输出无论写了什么，都不会改变某一项是否通过执行前检查。

Agent 插件（Pare-DSH）同样遵守：调用 CLI 的结构化接口，不直接枚举文件，不接收任意 shell 命令；写操作只接受 Pare 签发的计划 ID 并要求宿主可验证的审批绑定，没有审批能力时只开放扫描和计划预览。

## 8. 验收与验证

- 目录树遍历通过权限拒绝、损坏/变化、reparse、长路径、硬链接和跨卷 ID 用例。
- 不完整扫描明确报告缺口，不能把缺口算作零大小或清理依据。
- 同范围数据对拍须固定工具版本、卷、权限、范围和计量规则；差异按类别解释，不用单一百分比代替正确性判断。
- 计划外文件、审批后替换文件、保护路径、执行中断、磁盘空间不足和撤回冲突都必须验证为保留源数据或明确失败。
- 在金标准样本中，标记为必须保留的文件不得进入可执行批次。
- 性能目标在冷/热缓存和相同权限条件下通过本机 benchmark 之后再确定。
